# Contributing to Astrid

**[Start here: contribution workflow](docs/contribution-workflow.md)** · [Use an agent? Give it the main skill](skills/astrid-dev/SKILL.md) · [Find work](plans/index.md) · [Report a bug](https://github.com/banodoco/astrid-dev/issues/new)

Everyone can propose work. Claim an available queued project with a PR that changes only the Owner line in its `plan.md`, and the claim bot or a maintainer merges it; scope changes need review; implementation PRs carry actual source-bound evidence; completed projects need qualified integration and an independent completion review. A claim or review-queue label is not execution or merge permission.

**Writing or documentation?** Use the same contribution process—[find the right source and review path](docs/contribution-workflow.md#write-or-improve-documentation). Small fixes need only a focused PR. Public vision prose lives in [vision/](vision/README.md), project content in [plans/](plans/index.md), and product API docs with the owning product repo.

[Questions or blockers](https://github.com/banodoco/astrid-dev/issues/new?template=project-question.md) use ordinary issues or the relevant PR. Decisions that affect scope belong in the project pack, not a mandatory discussion hub.
